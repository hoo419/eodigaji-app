# 계정 전환 브라우저 테스트 · 2026-11-11

결과: 발견한 추천 조건 잔존 문제 수정 후 통과.

## 테스트 범위

로컬 서버 + 실제 Edge 브라우저 + 테스트 인증/DB 대역으로 진행했습니다. 동일 브라우저 컨텍스트와 같은 탭에서 쿠키/페이지를 유지하며 A → B → A 계정 전환을 수행했습니다. 중간 B 새로고침도 포함합니다. 실제 운영 사이트·Supabase 계정·메일·RLS·실 AI/지도 API를 검증한 결과는 아닙니다. 운영 배포는 하지 않았습니다.

## 재현 및 수정

수정 전 A의 저장 코스는 B의 저장 목록에 나오지 않았습니다. 그러나 A가 고른 연남/3만원 조건이 로그아웃 후 초기화되지 않아, 작업 상태가 없는 B의 새 코스 추천에 사용되는 문제를 재현했습니다.

로그아웃·로그인 계정 전환·세션 만료 시 현재 코스/프로필/대화/유지 조건뿐 아니라 지역·예산·검색어·선택 장소·화면 상태·처리 중 상태를 함께 초기화하도록 변경했습니다. 서버 데이터는 삭제하지 않습니다. 로그인한 계정의 작업 상태가 있으면 이후 해당 계정 데이터로 복원합니다.

이전 계정에서 시작한 HTTP 응답은 계정/화면 세대가 바뀌면 적용하지 않습니다. 대화 완료·오류 처리에서도 이전 계정 결과를 현재 대화에 추가하지 않습니다.

## 확인한 시나리오

1. A 로그인, 연남/1인 3만원 조건으로 코스 생성 및 상세 확인.
2. 코스 저장, A 전용 제목·메모 입력, 대화로 두 번째 장소 유지.
3. A 로그아웃 후 본문 제거 및 로그인 팝업 확인.
4. B 로그인 후 저장 목록 비어 있음, A 전용 제목·메모·대화·고정 장소 없음.
5. B 새 계획 조건은 기본값(성수/5만원), A의 연남/3만원과 분리.
6. B 새로고침 후에도 A의 코스 ID/제목/메모가 계정 응답에 없음.
7. B 자신의 코스 생성·저장.
8. A 재로그인 후 자신의 코스/메모/대화/연남 조건/유지 장소 복원, B 코스 없음.
9. A의 대화 응답을 지연시킨 상태에서 로그아웃하고 B 로그인. 늦은 A 응답이 B 화면/저장소에 섞이지 않음.
