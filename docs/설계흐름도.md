## 추천 및 다양성

```mermaid
flowchart TD
  Input[조건 입력 또는 AI 해석] --> Validate[조건 정규화·검증]
  Validate --> Catalogue[지역 장소 후보 조회]
  Catalogue --> Theme[카페·문화 실내 / 공원 실외 후보 생성]
  Theme --> Explicit[명시적인 실내외 조건 우선]
  Explicit --> Filter[테마 한 곳·분류 중복 금지·예산·시간 검사]
  Filter --> Rank[분위기·이동시간 점수]
  Rank --> Variety[최근 결과 감점·작은 난수]
  Variety --> Joint[상위 후보 세 테마 동시 비교]
  Joint --> Dedup[동일 집합 금지·장소 겹침 감점]
  Dedup --> Cards[유효한 코스만 최대 3개 표시]
  Cards --> Select[코스 선택]
  Select --> Detail[상세·번호 마커·방문 순서]
  Detail --> Mode[도보·대중교통·자동차 선택]
  Mode --> Result{실제 경로 조회 성공?}
  Result -- 성공 --> Path[실제 경로·구간별 정보]
  Result -- 실패 --> Fallback[미조회 안내·방문 순서 점선·외부 길찾기]
  Detail --> Cards
```

실외 분류가 부족한 기본 추천은 공원을 포함한 혼합 후보로 대체하고 표시한다. 조건을 충족하는 후보가 없으면 조건 변경을 안내한다. 후보가 하나뿐이면 중복 카드로 채우지 않는다.

## 로그인과 저장

```mermaid
sequenceDiagram
  actor U as 사용자
  participant UI as 앱 화면
  participant API as Node 서버
  participant Auth as Supabase Auth
  participant DB as Supabase DB
  U->>UI: 로그인 입력
  UI->>API: POST /api/auth/login
  API->>Auth: 비밀번호 인증
  Auth-->>API: 사용자·인증 토큰
  API-->>UI: HttpOnly 세션 쿠키·사용자
  UI->>API: GET /api/account
  API->>DB: 세션 사용자 ID 필터·사용자 토큰
  DB-->>API: RLS 적용 후 프로필·저장 목록
  API-->>UI: 계정 데이터
  U->>UI: 코스 저장
  UI->>API: POST /api/saved
  API->>DB: 사용자 ID·코스 ID로 upsert
  DB-->>API: 저장 결과
  API-->>UI: 성공 또는 오류
```

가입 시 인증이 필요하면 이메일 링크로 운영 주소에 복귀한 뒤 로그인한다. 게스트 저장은 서버 DB 대신 기기 localStorage를 사용한다.
