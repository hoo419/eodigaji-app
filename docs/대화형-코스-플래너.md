# 대화형 코스 플래너 · 2026-11-11

## 사용 흐름

코스를 선택한 뒤 **대화로 코스 수정**을 누릅니다. AI 대화 화면에는 현재 코스의 번호와 장소 이름, 유지 표시, 요청한 취향, 최근 변경 기록이 표시됩니다.

- “두 번째 카페는 유지하고 나머지는 바꿔줘.”
- “세 번째 장소는 빼고 이 카페를 그 자리에 넣어줘.”
- “첫 번째 장소에서는 45분 머물고 싶어.”
- “이동을 최소로 해줘.”
- “예산은 2만원으로 줄여줘.” → 충돌하면 장소 삭제·교체 방법을 질문 → “그럼 전시를 빼줘.”

AI 연결 시 자유로운 문장을 구조화된 코스 편집 명령으로 해석합니다. AI 키가 없는 샘플 모드는 일부 순번·이름 기반 명령만 해석하며, 모호한 요청은 질문합니다.

## 핵심 동작

1. AI 입력에 현재 코스, 실제 검색 후보, 최근 24개 메시지, 유지 장소·제외 장소·취향·최근 변경 기록·미해결 조건을 전달합니다.
2. AI는 새 코스 생성 / 기존 코스 편집 / 명확화 질문 / 특정 장소 검색 중 하나를 선택합니다.
3. 편집 명령은 유지·유지 해제·추가·교체·삭제·순서 이동·체류시간·이동 순서 최적화로 나뉩니다. 임의 장소 객체 대신 실제 후보 ID를 사용합니다.
4. 특정 장소가 후보에 없으면 실제 카카오 키워드 검색 후 AI가 결과를 다시 판단합니다. 한 요청당 검색 재판단은 한 번으로 제한합니다. AI 재호출도 일일 한도에 포함됩니다.
5. 서버가 복제한 코스에 명령들을 적용하고 중복·장소 수·유지 조건·지역·종류·실내외·비용·예상 이동 및 체류시간을 검증합니다. 하나라도 실패하면 코스를 바꾸지 않고 질문합니다.
6. 예산·시간 등 충돌한 요청 조건은 미해결 조건으로 기억합니다. 다음 응답에서 조정에 성공하면 해제합니다.
7. 성공한 편집은 같은 코스 ID의 새 revision입니다. 요청하지 않은 장소의 이름·메모·체류 정보는 보존합니다. **변경사항 저장**을 눌러야 저장 코스를 갱신합니다. 공유 버튼은 최신 코스를 먼저 저장하고 읽기 전용 공유본을 만듭니다.
8. 직전 코스/유지 조건 변경은 되돌리기로 복원할 수 있습니다. 되돌리기는 현재 화면의 초안을 바꾸며, 이미 저장한 코스를 자동으로 되돌리지 않습니다. 저장 버튼으로 다시 반영할 수 있습니다.

## 보관과 한계

- planningMemory는 기존 account_state 작업 상태에 포함되어 계정별로 보관합니다. 최근 유지 장소·제외 장소·취향·변경 요약·미해결 조건을 재로그인 후 복원합니다. 이 변경 자체는 추가 DB 테이블이 필요하지 않지만 앞선 account_state 마이그레이션이 아직 운영에 적용되어야 합니다.
- 유지 조건은 AI가 임의로 해제하지 못하도록 서버에서 해제 요청 문구를 확인합니다. 새 코스 전체 생성 시 유지 조건이 있으면 먼저 해제 여부를 질문합니다.
- 이동 최소화는 거리 기반 추정입니다. 최대 8개 장소의 순서 조합을 평가하며 실제 교통 최단 경로나 영업시간을 보장하지 않습니다.
- 조용함·혼잡도·로맨틱함·예약 가능 여부를 검증했다고 주장하지 않도록 모델에 지시합니다. 취향은 사용자 요청이며 확인된 업체 사실과 구분해 표시합니다. 실제 모델의 모든 표현을 자동 검증할 수는 없습니다.
- 대화창에는 최근 대화만 전달되지만 구조화된 조건과 계획 기억은 계속 전달합니다. 무한한 기억을 제공하지는 않습니다. 이전 장소 ID는 120개, 취향은 12개, 변경 요약은 20개로 제한합니다. 직전 변경 되돌리기는 현재 화면에서만 지원합니다.
- 이 checkout에는 실 API 키/운영 DB 설정이 없습니다. 실제 Gemini/Sol 자유 대화 품질, 검색 품질, 지연시간은 운영 연결 후 별도로 검증해야 합니다. 자동 테스트는 모델 응답·DB·장소 검색 대역을 사용하며 실제 유료 API는 호출하지 않습니다.
