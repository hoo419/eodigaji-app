# 계정·공유·블록 편집 (2026-11-10)

## 기능

- 이메일 계정 로그인 후 추천·탐색·대화·프로필·저장 기능을 사용할 수 있습니다. 서버 API에서도 인증을 검사합니다.
- 프로필, 저장 코스, 마지막 계획 조건·코스·대화를 사용자별 Supabase 데이터로 보관합니다. 로그아웃은 DB 데이터를 삭제하지 않습니다. 서버 재시작 후에는 다시 로그인하여 불러옵니다.
- 저장한 코스 → 블록 수정에서 드래그(터치 포함) 또는 위/아래 버튼으로 순서를 바꿀 수 있습니다. 장소 추가·삭제, 제목·시작 시간·메모·비용·체류시간, 구간별 이동수단과 예상 이동시간을 수정합니다.
- 변경사항 저장에 성공해야 계정의 저장 코스가 바뀝니다. 취소하면 원본을 유지합니다. 방문 시각·종료 시각·총비용을 다시 계산합니다.
- URL 복사는 서버에 공유 당시의 코스를 별도 저장하고 `/?share=<UUID>` 주소를 복사합니다. 클립보드 사용이 제한되면 직접 복사하는 입력란을 제공합니다.
- 수신자는 로그인 없이 공유 페이지를 볼 수 있습니다. 공유 페이지에는 수정·저장 버튼이 없으며 공유 데이터 수정 API와 DB UPDATE 권한도 없습니다. 소유자가 원본 코스를 수정해도 이전 공유 링크의 내용은 유지됩니다. 다시 공유하면 새로운 주소가 생성됩니다.
- 링크를 아는 누구나 볼 수 있으므로 코스 메모도 공유 대상입니다. 계정·프로필·대화 내용은 공유 데이터에 포함하지 않습니다. 공개 공유 목록은 제공하지 않습니다.
- 사진 URL이 제공된 장소는 해당 이미지를 먼저 사용하고, 없으면 예시 사진을 사용합니다. 사진을 불러오지 못하면 앱에 포함된 `place-example.svg`로 대체합니다. 예시 이미지임을 표시합니다. 현재 카카오 Local 검색 결과에는 실제 장소 사진 필드가 없습니다.
- 로고는 홈 화면으로 이동합니다. 공유 페이지에서 로고를 누르면 일반 홈으로 이동하며 로그인하지 않았다면 로그인 화면이 나옵니다.

## 기존 운영 DB에 적용

1. Supabase SQL Editor에서 `supabase/migrations/20261110_account_sharing.sql`을 실행합니다. 기존 프로필·저장 코스는 삭제하지 않습니다. 신규 DB라면 `supabase/schema.sql` 전체를 실행합니다.
2. 기존 서버의 SUPABASE_URL, SUPABASE_PUBLISHABLE_KEY, APP_ORIGIN 설정을 유지하고, APP_ORIGIN이 실제 공개 주소인지 확인합니다. 공유 URL은 이 주소를 사용합니다.
3. SQL 적용 후 새 서버 소스를 배포합니다. DB 적용 전 새 코드를 운영 배포하면 account_state 조회가 실패하므로 순서를 지켜야 합니다.
4. 실계정으로 로그인 → 프로필/코스 저장 → 편집 → 로그아웃 → 재로그인하고, 다른 브라우저에서 공유 URL을 열어 확인합니다.

현재 작업 폴더에는 운영 .env 또는 DB 관리 접속 설정이 없어 운영 SQL 실행과 배포를 수행하지 않았습니다. 테스트의 DB는 메모리 대역이며 실제 Supabase의 RLS 동작 검증은 운영 SQL 적용 후 별도로 확인해야 합니다.

## 검증

- `npm test`: 인증·계정 분리·재로그인·서버 재시작·공유 스냅샷 불변성을 포함한 HTTP 테스트.
- `npm run check`: 문법 검사.
- `node tests/account-browser.mjs`: 테스트 DB로 로그인·드래그·편집 저장·URL 복사·익명 읽기 전용·홈 이동·재로그인·PC/390px 모바일 화면 검증. 로컬 Edge와 번들 Playwright를 사용합니다.
- `npm run build:mobile`: 모바일 웹 자산 빌드. 네이티브 APK/IPA 배포는 별도이며 실계정 기능에는 mobile/config.json의 apiBase에 새 서버의 HTTPS 주소가 필요합니다.
