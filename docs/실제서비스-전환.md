# 실제 서비스 전환

## 이번 변경

- 카카오 실제 장소에 남은 샘플 표현을 수정하고 목록·코스 비용을 예상 금액으로 표시합니다.
- `APP_MODE=live`에서 AI·장소 설정이 없으면 해당 요청에 503을 반환합니다. 샘플 성공으로 대체하지 않습니다.
- `/api/ready`는 네 가지 서비스의 설정 여부를 확인합니다. 실제 인증 성공을 보장하는 검사가 아닙니다.
- `APP_ALLOWED_ORIGINS`에 명시한 출처만 허용합니다. Android 연결 시 `https://localhost`를 등록합니다.
- Dockerfile은 서버·화면 코드만 복사합니다. `.env`, APK, SDK, 비밀 키는 이미지에 포함하지 않습니다.
- `HOST`로 서버 바인딩을 지정하고 종료 신호를 받으면 처리 중인 요청을 마친 후 종료합니다.

## 사용자가 준비할 설정

1. Google AI Studio에서 키를 발급하고 `.env`의 `GEMINI_API_KEY`에 저장합니다.
2. Supabase 프로젝트를 생성한 후 Project URL과 publishable key를 `.env`의 `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`에 저장합니다. service_role 또는 secret key는 사용하지 않습니다.
3. Supabase SQL Editor에서 `supabase/schema.sql`을 실행합니다. 새 테이블을 생성하고 기존 동일 이름의 소유자 정책은 갱신하므로 해당 앱 프로젝트에서 실행합니다.
4. Supabase 이메일 인증의 Site URL을 테스트 중에는 로컬 웹 주소, 배포 후에는 실제 HTTPS 웹 주소로 설정합니다. 인증 메일 링크를 열고 앱으로 돌아와 로그인합니다.
5. 서버를 다시 실행하고 `node scripts/check-services.mjs --ai`로 연결을 검사합니다. AI 요청 1회가 발생하며 요금·한도는 계정 설정에 따릅니다.

비밀 키는 채팅이나 Git에 올리지 않습니다. 기존 카카오 설정은 유지합니다.

## 배포 구성

Docker를 지원하는 호스팅에서 이 프로젝트의 Dockerfile로 빌드하고, 호스팅 환경변수에 키를 입력합니다.
`APP_ORIGIN`은 실제 HTTPS 웹 주소, `APP_ALLOWED_ORIGINS=https://localhost`, `APP_MODE=live`를 설정합니다.
컨테이너 기본 포트는 4173이며 호스팅 제공자가 PORT를 지정하면 그 값을 사용합니다.
현재 PC에는 Docker가 확인되지 않아 컨테이너 빌드·클라우드 배포는 검증하지 않았습니다.

현재 세션·요청 제한은 메모리 저장이므로 단일 서버 인스턴스로 운용하며 재시작 시 재로그인이 필요합니다.
여러 인스턴스로 확장하기 전 공유 세션/요청 제한 저장소가 필요합니다.
호스팅 계정, 배포 대상과 비용 조건이 정해지지 않아 공개 서버는 아직 만들지 않았습니다.

## Android 연결

배포된 HTTPS 주소를 `mobile/config.json`의 apiBase에 넣고 `npm run android:build`로 다시 빌드합니다.
기존 APK는 자동으로 업데이트되지 않습니다. 카카오 JavaScript SDK 도메인에 `https://localhost`를 등록합니다.
네이티브 HTTP의 쿠키 유지, 가입·로그인·저장·로그아웃을 실제 Android 기기에서 확인해야 합니다.

## 실제 계정 검증 순서

회원가입 → 이메일 인증 → 로그인 → 프로필 저장 → 코스 저장 → 로그아웃 → 재로그인 → 저장 데이터 확인.
다른 계정으로 로그인해 첫 계정의 코스가 보이지 않는지도 확인합니다.
AI 대화는 예산·실내외 변경과 후속 대화 조건 유지, 지원하지 않는 지역 안내를 확인합니다.
API 키 입력과 SQL 실행 전에는 위 기능이 실서비스에서 완료됐다고 판단하지 않습니다.
