# 어디가지 기능설계서

기준일: 2026-10-14. 현재 소스 기준이며 실제 DB 적용 상태와 실기기 검증은 별도이다.

## 사용자 기능

| 기능 | 입력·전제 | 처리와 결과 | 예외 |
|---|---|---|---|
| 조건 추천 | 지역, 예산, 시간, 시작 시각, 분위기, 실내외, 이동수단 | 실제 장소 또는 샘플로 최대 3개 테마 코스 | 조건 불충족 시 변경 안내 |
| 코스 선택 | 추천 카드 | 선택 코스 상세·번호 마커만 표시 | 다른 코스 선택으로 복귀 |
| AI 계획 | 1~1500자 메시지·기존 조건 | AI 조건 해석 후 동일 추천 알고리즘 호출 | 연결 실패·요청 한도 안내 |
| 경로 확인 | 최대 4개 좌표·이동수단 | 도보·대중교통·자동차 실제 경로와 구간 정보 | 미조회 시 회색 방문 순서선·외부 길찾기 |
| 가입·로그인 | 이메일·비밀번호 | Supabase Auth·서버 세션 쿠키 | 이메일 인증 안내·오류 |
| 프로필 | 로그인·이름·취향 | 사용자별 JSON 프로필 저장 | 401 또는 입력 검증 오류 |
| 코스 저장 | 선택 코스 | 회원 DB, 게스트 기기 저장 | 실패를 성공으로 표시하지 않음 |
| 공유 | 선택 코스 | 네이티브 공유 또는 텍스트 복사 | 브라우저 기능별 대체 |
| 앱 설치 | 브라우저·지원 OS | PWA 또는 Capacitor | 설치 상태에서는 설치 버튼 숨김 |

## 추천 규칙

2~4곳, 동일 분류 중복 금지. 테마 장소 한 곳 필수, 식사 필수·가산점 없음. 예산·시간·실내외 조건 검증 후 분위기와 이동 편의성 평가. 기본 카페·문화는 실내, 공원은 실외 후보 우선. 실외 분류 부족 시 공원 포함 혼합 표시. 테마별 상위 18개 후보를 함께 비교해 동일 장소 집합을 금지하고 겹침을 감점한다. 최근 18개 결과에 감점, 품질 점수에 0~8 난수를 추가한다. 대안 부족 시 코스 수를 줄이거나 이전 추천 재사용 가능. 이력은 조건별 서버 메모리이며 개인별 영구 이력이 아니다.

## API 계약

| 메서드 | 경로 | 역할 | 인증 |
|---|---|---|---|
| POST | /api/plan | 조건 → recommendations 및 첫 코스 | 불필요 |
| POST | /api/chat | 대화 → 조건 해석·추천 | 불필요 |
| POST | /api/route | points·mode → actual·legs·segments | 불필요 |
| GET | /api/places | region → 장소 후보 | 불필요 |
| POST | /api/auth/signup, /api/auth/login | 인증·세션 생성 | 이메일·비밀번호 |
| POST | /api/auth/logout | 세션 제거 | 세션 있으면 토큰 무효화 |
| GET | /api/auth/user | 로그인 상태 | 선택 |
| GET | /api/account | 프로필·저장 목록 | 필수 |
| POST | /api/profile | profile 갱신 | 필수 |
| POST | /api/saved | course 저장 또는 remove 삭제 | 필수 |
| GET | /api/config, /api/health, /api/ready | 공개 설정·상태 | 불필요 |

JSON 요청 본문 최대 16KB. 인증 POST 분당 10회, 기타 POST 분당 30회 제한은 프로세스의 원격 주소 기준이다. ready는 설정 유무 검사이며 외부 연결 성공 보장이 아니다.

## 검증과 한계

56개 자동 테스트, 문법 검사, 모바일 자산 빌드로 검증한다. 비용·체류·실내외 분류는 검색 결과에 덧붙인 추정값이며 실제 영업 여부는 보장하지 않는다. 추천 일정 추정과 실제 길찾기 시간을 구분한다. 실제 사용자 가입 메일·iPhone 설치는 별도 검증 대상이다.
