## 이번 작업이전 파일

## 다른 PC에서 이어가기

1. ZIP을 새 로컬 폴더에 압축 해제합니다. Node.js 22 이상을 준비합니다.
2. 웹 샘플 실행은 프로젝트 폴더에서 `npm start`를 실행하고 `http://127.0.0.1:4173`으로 접속합니다.
3. 실제 서비스 개발은 `.env.example`을 `.env`로 복사한 뒤 별도로 보관한 키를 설정합니다. [연동 설정](연동-설정.md)을 참고하세요. 비밀 설정은 공개 ZIP이나 GitHub로 옮기지 않습니다.
4. `npm test`, `npm run check`로 확인합니다. 모바일 빌드 전에는 `npm ci`를 실행합니다.
5. Git 이력이 필요한 개발은 ZIP 대신 저장소를 `git clone`합니다. ZIP에는 `.git`이 없습니다.

## 기존 USB 프로젝트 갱신

USB의 변경 사항을 먼저 별도 폴더에 백업·비교한 다음 최신 공개 소스를 반영합니다. 기존 `.env`, `.git`, 개인 작업 파일, SDK·빌드 캐시는 일괄 덮어쓰기나 삭제 대상이 아닙니다. 로컬 변경이 있는 파일은 비교하여 병합합니다. 예전 파일이 있다는 이유로 무조건 삭제하지 않습니다.

Git 체크아웃이라면 작업을 저장한 뒤 `git fetch origin`으로 변경을 확인하고 병합합니다. Git 체크아웃이 아니라면 새 폴더에 ZIP을 풀어 확인한 후 기존 소스와 비교해서 복사합니다.

## 운영 서버와 모바일

GitHub 자동 배포가 연결되어 있지 않아 커밋만으로 Railway 서버가 바뀌지 않습니다. 재배포는 최신 소스로 별도 수행해야 합니다. 운영 서버 비밀 환경변수는 ZIP에 없습니다.

Android·iOS는 현재 오프라인 샘플 모드입니다. 실서비스 앱을 빌드하려면 `mobile/config.json`의 `apiBase`를 운영 HTTPS 주소로 설정하고 다시 동기화·빌드합니다. 이전 APK를 최신 배포와 동일하다고 간주하지 마세요.

## 패키지 다시 만들기

새 파일을 먼저 Git에 등록한 후 프로젝트 루트에서 실행합니다.

```powershell
./scripts/package-transfer.ps1
```

패키지는 Git 추적 파일만 포함하고 `transfer/` 및 ZIP을 제외합니다. 파일 누락, 해시 불일치 또는 비밀 파일 경로가 발견되면 생성을 중단합니다.
