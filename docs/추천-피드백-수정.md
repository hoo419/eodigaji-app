# 웹 피드백 수정 (2026-11-10)

## 반영한 동작

- 카페만/식당 제외를 categories와 excludedCategories에 보관하고 장소 선택 전에 필터링합니다. AI가 잘못된 응답을 주더라도 명시적 조건을 해제하지 않습니다. 뒤이어 예산만 변경해도 종류 조건은 유지합니다.
- 로맨틱 데이트는 사용자가 식사를 명시하지 않으면 카페만 추천합니다. 식당 포함 요청이 있으면 식사를 허용합니다. 업소 분위기를 검증했다고 표시하지 않습니다.
- 추천 목록과 선택 코스에 다른 코스 추천 버튼을 추가했습니다. 지난 제안의 장소 ID를 최근 120개까지 사용자 작업 상태에 보관하여 새 추천에서 제외합니다. 새 장소가 부족하면 이전 장소로 대체하지 않고 오류 안내를 표시합니다. 브라우저에서 보던 마지막 코스는 새 추천 성공 전까지 유지합니다.
- 실제 장소 검색 후보를 종류별 최대 15개씩 조회·캐시하고, 요청 시 이전 장소를 제외한 후보를 제공합니다. 추천기에 입력하는 후보는 종류별 균형을 맞춰 최대 12개로 제한합니다.
- 저장된 하트는 채워진 진한 빨간색과 저장됨 문구로 표시합니다. 하트 재클릭은 삭제하지 않습니다. 휴지통 버튼만 저장 코스를 삭제합니다.
- AI에 보내는 최근 대화를 8개에서 24개 메시지로 늘렸습니다. 종류 조건은 대화창 길이와 관계없이 구조화된 현재 조건으로 계속 전달합니다. DB에 대화를 저장하는 것과 모델에게 매번 맥락을 전달하는 것은 별개입니다.

## Sol 전환 상태

OpenAI 분기의 기본 모델과 .env.example을 gpt-6.1-sol로 변경했고, Responses API 구조화 출력 및 low 추론 설정을 적용했습니다. 두 공급자 키가 모두 있을 때 명시적인 AI_PROVIDER가 없으면 OpenAI를 우선합니다. AI_PROVIDER가 설정되어 있으면 해당 공급자를 사용합니다.

운영 확인 결과 공개 /api/config는 Gemini 사용 중이었습니다. 운영 환경의 정확한 GEMINI_MODEL 값은 공개하지 않아 확인하지 못했으며 코드 기본값은 gemini-3.8-flash입니다. 이 checkout에는 API 키나 운영 환경 설정이 없어 실제 OpenAI 호출/운영 공급자 교체/배포는 수행하지 않았습니다. 테스트는 대역 응답으로 API 요청 형식과 제약 준수를 검증합니다.

실제 전환에는 서버 비밀 환경변수 OPENAI_API_KEY와 AI_PROVIDER=openai, OPENAI_MODEL=gpt-6.1-sol 설정이 필요합니다. 계정의 모델 접근 권한·비용·지연시간과 실제 한국어 대화 품질은 전환 전 실호출로 확인해야 합니다.

공식 문서: https://developers.openai.com/api/docs/models/gpt-6.1-sol
대화 상태 관리: https://developers.openai.com/api/docs/guides/conversation-state

## 추후 점검
